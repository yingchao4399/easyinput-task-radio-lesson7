# 第七课补充实践：四槽任务电台语义样机

这是在 Windows 浏览器里运行的**本地语义样机**，用于把第七课 L0 链路图里的关键状态亲手试一遍。它已通过 Windows Raw Input 接收 EasyInput 实体 USB 按键 S1–S8，并将按键编号转给本地页面；没有接入设备录音、实体灯、板载扬声器、真实 Codex、ASR 或 TTS，不能作为课程 C4 完整真机验收。作业主路径仍是 L0；这里补充一个已实现的 L3 第五灯语义及 Host 状态实验。

## 运行

需要 Node.js 18+。在本目录执行：

```powershell
node server.mjs
```

浏览器打开 `http://127.0.0.1:4177`。无需安装 npm 依赖，也无需 API Key。运行核心检查：

```powershell
node --test
```

可选的实体 USB 按键桥接需要 Windows 和 Python；仅做输入转发时不需要安装 `hidapi`。板子连接电脑后，另开一个终端执行：

```powershell
python hardware_raw_input.py --seconds 600 --forward-url http://127.0.0.1:4177/hardware/input
```

页面先填写文字；实体 S1–S4 提交对应槽位，S5–S8 请求播放对应槽位的未听提醒。桥接只读取 `VID_303A&PID_1006` 的 USB 输入并发送按键编号到本机，不向板子写命令；桥接运行时页面无需保持焦点。未运行桥接时，页面处于前台也可直接接收同样的快捷键。S1–S8 均已逐键验证板子到本地页面的链路；旋钮输入仅验证到 Windows，未接入页面。调试详情见 [HARDWARE-DEBUG.md](./HARDWARE-DEBUG.md)。

`fixed-reminder.wav` 是本地生成的固定提醒音；可用 `python make_chime.py` 重建。

页面右上角的“导出状态快照”会把当前 D1–D5、四槽队列与最近事件保存成 PNG，方便记录调试证据。快照明确标注“浏览器模拟”，不能代替真机照片或视频。

## 这次 Vibe Coding 做了什么

- **S1–S4**：输入文字模拟 ASR 转写，进入对应槽位。相同槽位严格排队，不同槽位并行。执行器是明确标注的本地模拟器。
- **完成信号**：只有执行器返回 `task_complete` 事件才生成总结和未听结果。进程退出或任意其他事件都不算完成。
- **S5–S8 / D1–D4**：每个槽位保存未听结果；点击播放不删除。只有固定提醒音触发浏览器 `ended`，才向核心发送有效回执并消费一条结果。播放中断、新指令抢占、断网都保留未读。
- **D5 新语义**：改为“排队压力灯”。Host 队列等待数为 0 时灰绿，1–2 条时黄色，≥3 条时红色；设备离线时优先蓝色。它读取 Host 队列，不重复 D1–D4 的“有未听结果”。

## 四个手动调试动作

| 动作 | 预期观察 | 真相源 |
| --- | --- | --- |
| 在槽 1 连续发两条，同时槽 2 发一条 | 槽 1 第二条排队，槽 2 同时执行 | Host 槽位队列与事件记录 |
| 等任务完成，再点击“听回来” | D1 仍亮，直到提醒音完整播完 | 缓存未读状态与 `ended` 回执 |
| 播放途中点“中断播放”或发送新指令 | 播放停止，旧结果仍未读 | 未读队列与中断事件 |
| 槽 1 连发四条，再模拟断网 | D5 先显示排队压力，断网后优先蓝色；任务可继续在 Host 侧完成 | Host 等待队列与连接状态 |

## 证据边界

`node --test` 只验证本地状态机；浏览器操作验证页面和固定提醒音；实体 S1–S8 已验证 USB 输入到页面，旋钮已验证向电脑发送滚轮事件。播放中实体 S1 抢占尚未取得完整时序证据。没有验证设备录音、实体灯、Wi-Fi、云 ASR/TTS、Codex 日志、固件烧录或板载扬声器。若继续做课程 C4，需逐项留下真机证据，未测项明确写“未测”。
